# ai-engineering-from-scratch-demo

Runnable, verified example code for the lessons in
[`ai-engineering-from-scratch`](https://yennj12.js.org/ai-engineering-from-scratch/index.html)
— 511 lessons across 20 phases.

The curriculum teaches **mechanism**: attention written with a hand-built
`Matrix` class, LoRA written as three lines of tensor algebra, model responses
faked by a hash. That is a good way to learn. What it never shows you is the
**real toolchain doing the same thing**.

That gap is this repo's entire unit of value:

> For lesson *L*, the reference repo builds *X* from scratch.
> This repo runs the production equivalent of *X* and asserts where the two
> agree — and says plainly where they don't.

The most convincing artefact it produces is a **parity assertion**: the lesson's
own code is imported, the library is run on the same inputs, and the deviation
is printed.

```
phase 07 / lesson 03: stdlib attention vs torch: 5 check(s)
  ok   MHA output vs torch (float64)   n=48  max|d|=2.78e-16  atol=1e-12
  ok   head 0 attention weights        n=36  max|d|=1.11e-16  atol=1e-12
  ok   GQA 4Q/2KV vs enable_gqa=True   n=48  max|d|=2.22e-16  atol=1e-12
```

Your pure-stdlib attention *is* `torch.nn.MultiheadAttention`, to 2.8e-16.

See [DESIGN.md](DESIGN.md) for the reasoning behind every decision below.

## Quickstart

```bash
git clone https://github.com/yennanliu/ai-engineering-from-scratch   # the reference, as a sibling
uv sync --extra llm                       # or: math, vision, audio, agents, infra

uv run demo list                          # what is built
uv run demo run phases/07-transformers-deep-dive/03-multi-head-attention
uv run demo verify --tier T0              # what CI runs on every push
uv run demo coverage                      # honest completion table
```

`AIEFS_REF=/path/to/ai-engineering-from-scratch` if the reference lives elsewhere.

## Tiers

Phase 01 runs in 40ms on a laptop; Phase 08 wants an A100. Every demo declares
which world it lives in, and a demo your machine cannot host **skips cleanly
with an explanation** — never a stack trace.

| Tier | Means | Budget | CI |
|---|---|---|---|
| `T0` cpu-instant | stdlib / numpy / sklearn | < 10 s, no network | every push |
| `T1` cpu-heavy | torch-CPU, small HF checkpoint | < 5 min | nightly |
| `T2` api | a real provider call | < 20 s, < $0.02 | every push, **replayed** |
| `T3` gpu | needs CUDA / ≥ 16 GB VRAM | < 30 min | manual / rented runner |

T2 demos replay committed **cassettes** — real recorded responses, not
simulations. Free, offline, deterministic. `DEMO_MODE=live` re-records and
prints what it cost.

## Layout

Demo paths mirror lesson paths byte-for-byte, so a lesson URL maps to a demo
directory by string substitution and coverage is a `diff` of two trees.

```
demos/phases/07-transformers-deep-dive/03-multi-head-attention/
├── demo.yaml       # tier, budget, deps group, what it proves, parity target
├── README.md       # what it proves, how to run, expected output
├── run.py          # entrypoint; --explain works with nothing installed
├── tests/          # >= 3 assertions on the lesson's claim
└── cassettes/      # T2 only
```

## Contributing a demo

```bash
python scripts/scaffold.py phases/09-reinforcement-learning/04-q-learning-sarsa
# fill in every TODO, then:
python scripts/audit_demos.py      # structure gate: manifest, README, >=3 tests
python scripts/check_deps.py       # imports match the declared deps group
uv run demo verify <lesson>        # it runs, its tests pass, inside its budget
```

The gate is mechanical, not editorial. A scaffold does not pass it.

CI lives at `../.github/workflows/aiefs-demo-{t0,t1,t2-live}.yml` — GitHub only
reads workflows from the repository root, and this project is currently a
directory inside `ai_experiment` rather than its own repo. `t0` runs on every
push (structure gates, harness tests, T0 demos, and T2 demos **replayed
offline**); `t1` nightly; `t2-live` weekly, to re-record cassettes and report
what drifted.
